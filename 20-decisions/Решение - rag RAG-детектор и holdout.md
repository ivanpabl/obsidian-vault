# Решение - rag: RAG-детектор и holdout

## Контекст

Требовалось отличать настоящие сбои от подозрительных окон в логах BGL. Было проверено несколько гипотез организации пайплайна: LangChain, агент LangGraph, zero-shot LLM, kNN и другие (предыдущая версия — тег `v1-experiment` в репозитории).

## Решение

- Оставлен RAG-детектор: эмбеддинг шаблона кандидата → поиск 5 похожих шаблонов в базе знаний (FAISS, сходство ≥ 0,7) → промпт с похожими случаями → вердикт LLM (Ollama, qwen2.5:3b).
- Оценка качества — строго на holdout по шаблонам: база знаний строится без проверяемого шаблона, validation-период (11.2005–01.2006) хранится вне проекта в `~/rag-holdout`.

## Причина

- Сравнение в `docs/results.md`: RAG-детектор распознаёт новые типы сообщений лучше всех (F1 по шаблонам 0,73 против 0,67 у TF-IDF); без поиска похожих случаев LLM находит лишь 44% аномалий — контекст похожих размеченных примеров критичен.
- Holdout по шаблонам показывает работу на сообщениях, которых нет в базе знаний — режим `category` прячет целые категории сбоев и даёт завышенную оценку.

## Последствия

- Параметры (k, промпт, модель) принимаются только по dev и holdout на train — не по validation.
- Для новых решений по качеству каждый прогон фиксируется в `results/experiments.csv`.
